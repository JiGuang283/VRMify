# PMX → VRM 转换说明

纯 Python 标准库实现，不依赖 Blender、mmd_tools、Unity、UniVRM、pygltflib。
（GitHub 上那个 `aia7520-gif/pmx2vrm` 是 Blender + mmd_tools + VRM 插件的方案，
需要装 Blender 和两个插件；这里直接读写二进制，不需要任何外部程序。）

## 工具清单

| 文件 | 作用 |
|---|---|
| `formats/pmxio.py` | 完整 PMX 2.0 读写（含表情 offset、IK、付与、刚体、关节） |
| `formats/vrmio.py` | GLB/glTF 容器读写 + PNG 编码 + BMP/TGA 解码 |
| `convert/pmx2vrm.py` | **PMX → VRM（1.0 / 0.x）** 入口：`convert()` 和命令行 |
| `convert/vrmconv/` | 各阶段：`humanoid`（骨骼映射、T-pose）、`skeleton`（节点树、占位骨）、`mesh`、`materials`（MToon）、`expressions`、`springbone`、`vrm_ext` |
| `gfx/web_preview.py` | 三维预览（three-vrm）：MToon、SpringBone、表情和导入软件后一致 |
| `tools/qa/` | VRM 结构 / 官方 Schema 检查、SpringBone 动态测试（见 `tools/README.md`） |

## 常用命令

```powershell
# PMX → VRM 1.0（默认）
python convert/pmx2vrm.py "model.pmx" -o "model.vrm"

# PMX → VRM 0.x（老软件/老 SDK 才需要）
python convert/pmx2vrm.py "model.pmx" --spec 0x --title "名字" --author "作者"

# 三维预览转换结果
python gfx/web_preview.py "model.vrm"

# 检查 VRM（结构 + 官方 Schema）
python tools/qa/check_vrm.py "model.vrm"
```

`pmx2vrm.py` 主要参数：

| 参数 | 说明 |
|---|---|
| `--spec 1.0` / `--spec 0x` | VRM 规范版本，默认 1.0 |
| `--scale auto` | 默认。归一化到 1.6 m；也可给具体倍率 |
| `--rotate auto` | 默认按版本决定；`none` / `y180` 可强制 |
| `--flip-winding` | 强制反转三角形绕序（默认**自动判定**，通常不需要） |
| `--force-double-sided` | 所有材质强制双面（仍有镂空时的兜底） |
| `--keep-pose` | 保留原始姿势；默认把 A-pose 手臂抬成 VRM 要求的 T-pose |
| `--outline` | 按 PMX 的轮廓线设置写出 MToon 描边（默认不描边） |
| `--dense-morphs` | 表情用密集存储（默认稀疏存储，文件小很多） |
| `--no-spring` | 不把 PMX 物理转成 SpringBone（默认转换，仅 VRM 1.0） |
| `--no-spring-skirt` | 跳过下半身（hips / 腿）下的物理链，通常是裙摆 |
| `--spring-stiffness k` | SpringBone 硬度整体倍率，默认 1.0 |
| `--spring-gravity g` | 头发等的 SpringBone 重力，默认 0（保持原造型） |
| `--spring-gravity-skirt g` | 裙摆类的 SpringBone 重力，默认 0.1（抬腿时裙片落回腿上） |
| `--no-spring-center` | 不设 SpringBone center（默认以模型根节点为 center，人物整体移动时头发/裙摆不会被甩） |
| `--max-morphs N` | 只导出前 N 个表情；`0` = 完全不导出 |
| `--title` / `--author` | 写进 VRM meta |

## 坐标系（这部分决定了模型朝向对不对）

| 格式 | 正面 | 角色左手侧 | 上 | 手性 |
|---|---|---|---|---|
| PMX（MMD） | **-Z** | **+X** | +Y | 左手系（DirectX） |
| VRM 0.x（glTF） | **-Z** | **-X** | +Y | 右手系 |
| VRM 1.0（glTF） | **+Z** | **+X** | +Y | 右手系 |

因此（2026-09-18 起的实现）：

* PMX 与 glTF 手性相反，同一组数字直接搬过去是**镜像人形**，必须反射一个轴：
  * PMX → VRM 0.x：X 取反。
  * PMX → VRM 1.0：Z 取反。
  * 「绕 Y 轴旋转 180°」是纯旋转，改不了手性，转出来左右是反的——别改回去。
* 反射会把「从外面看逆时针」颠倒成顺时针，所以**绕序要反转**。
  转换器用「反射后的数据」做「几何面法线 vs 顶点法线」投票自动判定，
  日志里会打出 `绕序自动判定（手性修正后）：与法线同向 N 面 / 反向 M 面 → 需要反转`，
  正常情况下就是判「需要反转」。
* 尺寸：MMD 约 20 单位 ≈ 1.6 m，所以换算倍率约 0.08（VRM 侧 1 单位 = 1 米）。
  表情（morph target）的偏移量同样要乘这个倍率。

### 绕序判定的实测依据

坐标系的结论不要靠推理，用数据说话，两个都很好测：

1. **正面朝向**：用脚尖骨骼减脚踝骨骼。
   云岫飞袂：`左つま先.Z − 左足ＩＫ.Z = −1.195` → 脚尖朝 −Z → PMX 正面 −Z。
   真实 VRM 0.x（VRoid 素体 / KizunaAI）：`leftToes.Z − leftFoot.Z = −0.095` → 同样 −Z。
2. **绕序**：拿每个三角形的几何法线（`(v1−v0)×(v2−v0)`）去点乘顶点法线，投票。
   抽样 6 个模型（YYBMiku / Rikka / 夕刻ロベル / シエン / ScaleMMD / 云岫飞袂）
   都是压倒性同向（例如 47340 : 202）→ 从外面看逆时针，与 glTF 一致。

> 早期版本硬编码「必须反转绕序」，结果模型被背面剔除，表现就是
> **大面积镂空 + 轮廓线糊成一片黑**。现在已改为自动判定。

### 万一还有镂空

先看日志里 `绕序自动判定` 那行。如果确实判定错了（反向面占多数），
手动加 `--flip-winding`。如果是模型本身有薄片几何（头发、裙摆、飘带）
依赖双面渲染，就加 `--force-double-sided`，或勾选界面上的「材质强制双面」。

如果导入某个软件后发现**模型背对你**，把 `--rotate` 手动反过来；
如果发现**模型破面/内外翻转**，加 `--keep-winding`。

## PMX → VRM 的映射

| PMX | VRM / glTF |
|---|---|
| 骨骼层级 | glTF 节点（只有平移，无旋转无缩放，符合 VRM 的静止姿势约束） |
| 骨骼绝对坐标 | `skin.inverseBindMatrices`（纯平移的逆） |
| 顶点权重 BDEF1/2/4、SDEF、QDEF | `JOINTS_0`（ushort×4）+ `WEIGHTS_0`（float×4，已归一化）；SDEF 退化成线性混合 |
| 付与 100% 的同位置骨（足D / ひざD / 足首D 等） | 权重和子骨并入付与親（VRM 没有付与机制，见下文） |
| A-pose 手臂 | 默认重摆成 T-pose（骨骼和顶点一起转，`--keep-pose` 关闭） |
| 材质 | 1.0：glTF 材质 + `VRMC_materials_mtoon`；0.x：glTF 材质 + MToon `materialProperties`（见下文） |
| 材质颜色 | 按 MMD 着色公式 `clamp(漫反射 × 0.6 + 环境色)` 计算；1.0 写入时从 sRGB 换成线性值 |
| toon 贴图（含共享 toon01～06） | MToon 的阴影色（toon 最下端）、亮部色（最上端）和明暗交界（shadingShift / Toony） |
| 透明 | 看漫反射 alpha **和贴图的 alpha 分布** 自动选 OPAQUE / MASK / BLEND |
| 加算球面贴图（.spa） | MToon 的 matcap（1.0 `matcapTexture`，0.x `_SphereAdd`） |
| 轮廓线 | `--outline` 时写 MToon 描边（宽度按 edge_size，颜色取 edge_color） |
| 贴图 | 嵌入 GLB。PNG/JPEG 直接透传，BMP/TGA 现转成 PNG；不支持的（DDS 等）跳过 |
| 顶点表情（含グループ展开） | morph target（默认稀疏存储）+ VRM expression |
| 材质表情 | expression 的 `materialColorBinds`（0.x：`materialValues`），用于显示/隐藏部件 |
| 物理刚体（mode 1/2）+ 关节 | `VRMC_springBone` 的 springs（仅 1.0，见下文） |
| 跟随骨骼的刚体（mode 0） | SpringBone 碰撞体（球 / 胶囊；盒近似成胶囊） |
| 表情名 | 自动对应 VRM 预设（まばたき→blink、あ→aa、怒り→angry …）；MMD 的「上」「下」是眉毛表情，不映射成 lookUp / lookDown |

骨骼名 → VRM humanoid 的对应（下半身→hips、上半身→spine、上半身2→chest、
首→neck、頭→head、左/右腕→UpperArm、左/右ひじ→LowerArm、左/右手首→Hand、
左/右足→UpperLeg、左/右ひざ→LowerLeg、左/右足首→Foot、左/右つま先→Toes、
左/右目→Eye）。`両目` 是双眼共用的控制骨，不映射。

手指按规范版本区分：

| MMD | VRM 1.0 | VRM 0.x |
|---|---|---|
| 親指０ / １ / ２ | ThumbMetacarpal / Proximal / Distal | ThumbProximal / Intermediate / Distal |
| 親指１ / ２（没有 ０ 的老模型） | ThumbProximal / Distal | ThumbProximal / Intermediate |
| 人指・中指・薬指・小指 １ / ２ / ３ | Proximal / Intermediate / Distal | 同左 |

两个版本都没有「食指～小指的 Metacarpal」，所以 `人指０` 之类不映射。

### 材质

* **透明模式**：以前只看漫反射 alpha，贴图自带透明通道的材质（头发高光层、瞳孔、
  镂空裙摆）全被写成 OPAQUE，透明区域画成实心——实测头发被盖成一片黑、眼睛全黑。
  现在会解码贴图的 alpha（纯 Python，只解 alpha 通道并抽样，2048² 约 0.3 秒）：
  半透明像素占可见像素比例 < 30%（只有抗锯齿边缘）→ MASK，否则 → BLEND。
  会被材质表情隐藏的不透明材质用 MASK，才能真正隐藏。
  BLEND 材质按 PMX 材质顺序写 `renderQueueOffsetNumber`，保持叠加层的绘制顺序。
* **MToon**：1.0 写 `VRMC_materials_mtoon`（阴影贴图 = 主贴图），
  UniVRM / three-vrm 导入后是卡通着色而不是写实 PBR。
* **toon → 阴影**：MMD 里颜色乘上 toon 贴图 `toon(v)`，v = 0.5 − 0.5·N·L；自阴影（投影）取
  最下端 `toon(1)`。所以阴影色 = toon 最下端、亮部色 = 最上端，明暗交界在亮度降到一半的
  v_mid：`shadingShift = 2·v_mid − 1`，过渡宽度 Δv → `shadingToony = 1 − Δv`。
  星铁 / 鸣潮 / 原神的皮肤 toon 在 v≈0.75 以后才变暗，换算出 shift≈+0.5～0.7、阴影色是浅粉：
  脸上基本全亮、只有头发等的投影是粉色——和原生 VRoid 皮肤（0.x `_ShadeShift −1` /
  `_ShadeToony 1`，阴影色 (0.97, 0.81, 0.86)）的表现一致。共享 toon01～06 的颜色取自
  three.js MMDLoader 内嵌的那组；没有 toon 的材质（实际几乎都是眼睛、眉睫、嘴、表情贴片）
  不画阴影，和 VRoid 的眼睛、眉毛一致。以前一律「阴影 = 亮部 × 0.8」的灰色。
* **颜色空间**：glTF 的 `baseColorFactor` 和 VRM 1.0 MToon 的各个颜色因子规定是**线性值**，
  MMD 的材质色和 toon 贴图却是 sRGB 值（gamma 空间里直接相乘）。以前原样写进去：阴影色 0.8
  实际显示成 sRGB 0.9，只暗 10%，游戏里的环境光一照就看不出阴影；星铁的皮肤贴图本身又浅，
  整张脸又白又平。现在 1.0 输出统一换成线性值（a·b 在 gamma 空间的乘法正好对应线性的
  lin(a)·lin(b)）。0.x 的 `materialProperties` 本来就是 gamma 值，不转。
  0.x 的 MToon 以前阴影色写死成粉色且没有阴影贴图（暗部一片粉）、透明材质的混合参数
  等于不透明、单面材质 `_CullMode` 写成了剔除正面——都已修正。
* **乘算球面贴图（.sph）**：MToon 没有对应项，会被忽略（日志里有提示）。

### 物理 → SpringBone（VRM 1.0）

目标是**表现和原生 VRM 一致**（不是复刻 MMD 的 Bullet 物理）。参数按 VRM 官方 / VRoid 示例模型
（AvatarSample_B、VRM1_Constraint_Twist_Sample、Seed-san、AliciaSolid）在同一套动作
（待机放下手臂、转身、走路、抬腿）下的实测表现校准。

* **拆链**：挂了物理刚体的骨（humanoid 骨、已并入付与親的骨除外）从「自己动、父骨不动」处
  开始沿子骨走成链；分叉处子树最深的一支继续，其余另起一条链。链尾没有子骨的补一个
  `xxx_tail` 节点，否则最后一节不会摆。
* **分类**：挂在 hips 下的链，以及挂在躯干上但垂到胯部以下的链（侧面裙片、腰后飘带）算
  「裙摆类」；挂在手臂、腿、脚上的是「四肢配饰」（袖子、手肘吊坠、鞋带、腿环）；
  其余（头发、胸前饰品等）算「头发等」。
* **抽稀**：MMD 物理链切得很细（后发 1.2 m 分 24 节），原生发束是 3～7 节、每节 7～15 cm。
  所以头发等每节至少 12 cm，中间的骨刚性跟随上一个关节；裙摆类只并掉 5 cm 以内的——
  SpringBone 只在关节点检测碰撞，节太稀大腿会从关节之间穿过去。
  抽稀后相邻关节会改挂成**直接父子**（世界位置不变）。规范虽允许 joints 隔代，three-vrm 却按
  「子关节相对它直接父节点的位置」取静止方向，隔代的链在拐弯处（前裙片转到侧裙片）第一帧就会
  被转开——鸣潮·爱弥斯的侧裙实测偏了 24 cm，改挂后 2.4 cm。
* **硬度按「每帧回正角度」换算**：`stiffness` 是每秒移动的米数，不随节长缩放，同样的值在短节上
  力量大得多。`stiffness = ω × 节长 × 60`：头发等 ω=0.15（原生发束约 0.1～0.25 rad/帧），
  裙摆类 ω=2.0（密集的长裙需要更硬，才能撑住造型、少穿模）。
  **下限 2.0**：原生模型的硬度基本是绝对值 0.5～4，和节长无关；只按角度换算的话，3 cm 的胸部物理骨
  硬度只有 0.25，走路时整个翻过去（胸部衣物跟着乱抖），手肘吊坠也一样。
  **上限 10**：翅膀、长飘带的最后一节很长，按角度换算会到 50 以上，同样每帧拉过头（刻律德拉的翅膀
  跑步时末端颤动 70→35）。
  **四肢配饰里挂在手臂上的链 ω=0.5**：手臂是全身摆得最快的部位，按头发的 0.15 换算时，长袖跑步时
  末端颤动是头发的 5～8 倍（秧秧的大袖 45）；0.5 时降到 12，仍有明显摆动。
* **阻力**：头发等 0.6，裙摆类 0.6（跑步时裙摆末端颤动 26→17）。
* **重力**：头发等 0（加了会把散开的发型拉垂）；裙摆类 0.1。
* **不模拟的短链**：总长不足 5 cm 的链（3 cm 的胸部物理骨等），以及不足 12 cm 的四肢配饰
  （手肘吊坠、鞋带、脚踝蝴蝶结）。它们几乎看不出摆动，只会在末端高频颤动——四肢摆得快，弹簧追不上；
  跟着骨骼刚性移动更自然（开拓者的鞋带跑步时末端颤动 114，是全身最高）。
* **center = 模型根节点**（默认）：在模型自身的空间里模拟，应用里人物整体移动（走路的根运动）时，
  头发/裙摆不会因惯性被甩、往后拖压到腿上。实测走路时头发摆幅 0.73→0.15、胸部配饰 0.28→0.05、
  裙摆穿进大腿的顶点 10→3。原地动作不受影响；想要「走路时头发往后飘」可以 `--no-spring-center`。
* **碰撞**：跟随骨骼的刚体转成碰撞体（挂在 足D 上的改挂到 足；手臂的跟着 T-pose 一起转），
  按 PMX 碰撞组/掩码决定每条链和哪些碰撞体碰撞。头发也碰手臂（和 VRoid 一致）。
  四肢配饰不碰自己那条手臂/腿的碰撞体；挂在手臂上的链（手肘吊坠、袖子）完全不碰撞：转 T-pose 时
  它们跟着手臂转了，动画放下手臂后静止方向斜着指向身体，碰撞会把它们卡在身体另一侧来回翻。
  裙摆类 `hitRadius` 至少 4.5 cm；静止时确实贴着碰撞体的那几节缩到刚好不重叠（可以低于下限，
  否则开始模拟就被推开，长裙会从根部被撬开）。注意 SpringBone 用「这一节的半径、在尾端位置」
  做检测，所以只看各节尾端，链根埋在碰撞体里没关系。某节尾端静止时就在碰撞体里的，整条链不与它碰撞；
  例外是**裙摆和大腿**：PMX 的大腿刚体常比腿粗，贴腿的短裙静止时就在里面，这时给这条链另配一个
  缩小到刚好让开静止裙片的同位置碰撞体，而不是让这条腿完全拦不住裙片（穗穗走路时进了腿里的裙摆
  关节 4.2%→1.7%）。
* **舍弃**：PMX 里链与链之间的横向关节（裙摆常见）在 SpringBone 里无法表达，日志会提示数量。

实测（沃雅妮莎，three-vrm）与原生模型对比：

| 指标（按链长归一） | 原生模型 | 旧版（逐骨、按节数放大硬度） | 现在 |
|---|---|---|---|
| 头发 抖动/形变比：温和转身 | 5.6～7.3 | 12.1 | 6.3 |
| 头发 抖动/形变比：走路 | 14～20 | 33 | 17.4 |
| 头发 放下手臂后的偏移 | 0.02～0.06 | 0.14 | 0.03 |
| 带根运动的走路：头发摆幅 / 抖动 | 0.84～1.40 / 18～28 | — | 0.15 / 13 |
| 带根运动的走路：胸部物理骨、配饰摆幅 | 0.20（VRoid B） | 1.99（翻转） | 0.05 |
| 带根运动的走路：裙摆穿进大腿的顶点（最多/平均） | — | 36 / 22 | 3 / 1 |
| 走路时末端 8 Hz 以上的颤动：头发 / 裙摆（60 fps） | 2.6～6.3 / 3～22 | — | 1.8 / 8.5 |
| 同上，30 fps | 5.3～16.3 / 7～58 | — | 3.5 / 12.0 |

把腿抬到 70° 这类大动作时，裙摆最上面一圈（直接挂在下半身上）仍会和大腿根部有少量重叠，
这是 SpringBone 本身的限制，原生模型同样如此。手感不合适可以先用 `--spring-stiffness`
整体调，导入 Unity 后也可以在 UniVRM 的 SpringBone 里逐条调。

### 骨骼结构的自动修正

* **付与骨合并**：很多 MMD 模型的腿部网格权重全在 `足D / ひざD / 足首D` 上，
  D 骨靠付与回転 100% 跟随 `足 / ひざ / 足首`。VRM 没有付与，而 humanoid 指向的是
  `足`，原样导出时转大腿网格完全不动。转换器把「付与回転率 1、和付与親同位置」的骨
  的权重和子骨并到付与親上（日志：`付与骨合并：N 根`）。付与率不是 1 的
  （腕捩1 的 0.25、腰キャンセル 的 -1 等）不处理。
* **层级修正**：VRM 要求每个 humanoid 骨都在规范父骨位的子树里。MMD 的 上半身 和
  下半身 是「腰」下的兄弟骨，不修的话转 hips（全身朝向）只有下半身跟着转。
  转换器会把 上半身 改挂到 下半身 下（日志：`骨骼层级：spine（上半身）不在 hips…`）。
  静止姿势下节点只有平移，改挂不影响顶点位置。
* **T-pose**：VRM 规范要求 T-pose，MMD 模型多是手臂下垂 30～40° 的 A-pose。
  默认把上臂、前臂对齐到水平 ±X，子骨与顶点（含法线、表情偏移）按蒙皮权重一起转；
  腕補助 这类付与骨按付与率跟转。
* **占位骨**：缺少必需骨骼（1.0 为 15 根，0.x 另加 chest、neck）时自动生成 `vrm_xxx`
  占位节点，挂在规范要求的父节点下；如果模型里已有本该挂在它下面的 humanoid 骨
  （比如缺 spine 但有 chest），会把那根骨一起改挂到占位骨下，保证层级合法。

## 已知限制

1. **不支持的贴图格式**：KTX2 / WebP 会被跳过（材质退化成纯色）；DDS（DXT1/3/5）会解码成 PNG。
2. **物理**：PMX 物理只转成 VRM **1.0** 的 SpringBone（近似映射，见上文），0.x 不转。
3. **材质效果**：加算球面贴图转成 matcap，toon 贴图换算成阴影色和明暗交界；乘算球面贴图、
   共享 toon07～10 在 VRM 侧不保留。
   材质表情只转换漫反射色和环境色（即显示颜色和透明度），高光、轮廓线等其他项忽略。

   ⚠️ 读 toon 时的一个坑：PMX 材质的 toon 字段宽度由「共有Toonフラグ」决定，读写反了会把
   「不使用 toon」当成 `toon01.bmp`（其他格式 → PMX 的转换器写出的材质都是 `toon_flag=0` + `toon=-1`）：

   | flag | 含义 | 字段 |
   |---|---|---|
   | `1` | 共享 / 内建 toon | **1 字节编号**，引用 MMD 的 `Data/toon01.bmp` … `toon10.bmp`，**编号 0 就是 `toon01.bmp`** |
   | `0` | 本模型纹理表里的贴图 | 纹理索引宽度，**`-1` = なし（不使用）** |

   「编号 0 = `toon00.bmp` = 不使用」是误解 —— MMD 的 `Data/` 目录里没有 `toon00.bmp`，
   mmd_tools 源码里写死了 `toon%02d.bmp % (shared + 1)`。本工具 2026-09-24 之前就是错的那个写法。
4. **骨骼表情**：PMX 的骨骼表情（kind 2）在 VRM 里没有对应物，会被忽略。
5. **T-pose 重摆**：用的是线性蒙皮（LBS），肩部权重混合区在大角度重摆时会有轻微收缩。
6. 表情默认用 glTF 稀疏 accessor 存储，只存实际动到的顶点（实测 62.7 MB → 20.1 MB）。
   个别老软件不支持稀疏 accessor 时可以加 `--dense-morphs`。
