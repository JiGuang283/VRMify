モデルコンバーター

さまざまなモデル形式のファイルを .pmx ファイルに変換して出力できます。

サポートされる変換方向：
FBX／unitypackage → PMX
VRM（0.x／1.0）→PMX
PMX → VRM（0.x / 1.0）
uemodel → PMX
PMX → uemodel
psk / pskx → PMX 
PMX →FBX
PMX → psk / pskx
XPS → PMX

macOS、Linux バージョンが必要な場合は、こちらからダウンロードしてください。
https://github.com/SaraKale/Model-To-PMX/releases

使用方法：
1. ダブルクリックしてModelConvert.exeを実行。
2. ファイルをドラッグしてここにドロップするか、ドラッグ＆ドロップエリアをクリックしてファイルを選択してください。
3.「タスク」ドロップダウンボックスでは変換方向を手動で指定でき、デフォルトでは拡張子により自動判断される。
4.変換結果とログは左下にあり、モデルプレビューは右欄の全列です。

注意事項：

－モデルの縁に黒い線が入る：本ツールは PMX を出力する際、MMD の輪郭線を既定でオフにします。
  それでも黒い縁が見える場合は、MMD / PMXEditor で全マテリアルを選択し、輪郭線がオフになっていることと
  「両面描画」にチェックが入っていることを確認してください。
－穴が残る：まずログの「巻き順の自動判定」の行を確認してください。判定を誤った場合は --flip-winding、
  髪や裾などの薄い形状で両面描画が必要な場合は --force-double-sided、
  または画面の「材質強制両面」にチェックを入れてください。
－モデルがカメラに背を向ける：FBX に「どちらが正面か」というフィールドはないため、判定を誤るのは普通のことです。
  FBX オプション画面の「向きの自動判定」（既定でオン）にチェックを入れると、結果と根拠がログに出力されます。
  それでも背を向ける場合は「強制的に 180° 追加回転」（コマンドライン --face-180）にチェックを入れてください。
  X と Z を同時に反転するだけなので、頂点 / 面 / ボーン数には影響しません。
  XPS と PSK の軸変換は固定マッピングなので、この影響を受けません。
－透明になるべき場所が透明にならない：全体が半透明でゴーストが出る場合は、
  ゲームのテクスチャが alpha を発光マスクとして使っていることが多いです。
  --alpha strip（画面では「すべて除去」）を使ってください。通常は既定の auto を推奨します（1 枚ずつ判定します）。
  レース / 薄紗 / 髪の毛先が硬いエッジになる場合は、本当の透明が削られたためです。auto か keep に戻してください。
  どの設定でも元のテクスチャは書き換えられません。alpha 除去の結果は「名前_noalpha.png」という複製に書き出されます。
－体の上に灰色の板がかぶる：ゲームの FBX には、マテリアルもテクスチャもない EffectMesh が含まれることがよくあります。
  UV がアトラス全体に広がっており、「テクスチャが反転している」ように見えますが、UV はまったく正しいです。
  本ツールはマテリアルのないメッシュを既定でスキップし、ログに「skip メッシュ名」と出力します。
－FileNotFoundError が出る：Windows はパス全体の長さを既定で 260 文字に制限しているため、
  パスが深いとこのエラーが出ます。エラーに出るパスは一見まったく正常です。
  本ツールは自動で拡張長形式に切り替えるようになりました。レジストリの変更・管理者権限・再起動は不要です。
  古いバージョンをお使いの場合は最新版へ更新してください。応急処置としては、
  ファイルをドライブ直下に近い場所（例：D:\model\）へ置いてから変換してください。
  これは日本語パスの問題ではありません。日本語・中文・スペース・角括弧はいずれも問題なく、
  関係するのは全体の長さだけです。
－MMD が「MMDではエンコード方式がUTF16のPMXファイルしか読み込めません」と表示する：
  MMD が読めるのは UTF-16LE のみです。この表示が出た場合、ファイルは実際には UTF-8 です。
  本ツールが出力する PMX はすべて UTF-16LE です。
－PmxEditor が「アンカーデータの読み込みに失敗しました」と表示する：これは PmxEditor のエラーで、
  PMX ファイル自体とは関係ありません。モデルの隣にある同名の .psk を自分のアンカーデータとして
  解析してしまっただけです。OK を押せばモデルは通常どおり読み込まれます。
  完全に出なくするには：PMX を別のフォルダへ移すか名前を変える、
  または PmxEditor の [ファイル] → [アンカーデータの自動読み込み／保存] をオフにしてください。
－ドラッグ＆ドロップは Windows でのみ使用できます。その他の OS では「参照」ボタンでファイルを選択してください。
－設定ファイル config.json には言語 / UI 拡縮 / タスク方向 / 各オプションが記録され、
  削除すると既定値で再作成されます。

既知の制限：

－FBX：バイナリ FBX 7.x と ASCII FBX のどちらも読み込めます。
－テクスチャ：.dds（DXT1 / DXT3 / DXT5）はネイティブでデコードできます。
  KTX2 / WebP は非対応で、単色に劣化します。
－物理：PMX の剛体 / ジョイント ↔ VRM SpringBone は相互変換されません。
－マテリアル効果：.sph / .spa / toon テクスチャは VRM 側では保持されません。
  どの方向で出力する PMX も Toon を使用しません。
－ボーン名：FBX 変換では英語のボーン名（Hips、Spine …）を保持するため、
  既成の MMD モーション（.vmd）にはそのままではマッチしません。
  PMXEditor で一括して日本語標準名に変更してください。私が作成した PE ボーン整理プラグインが使えます：
https://www.bilibili.com/video/BV1MfYX6JEhE/
https://www.youtube.com/watch?v=zZj-I4YgIDY
https://www.nicovideo.jp/watch/sm46811122
  PSK は別ルートです。3dsMax Biped の Bip001 系の名前は既定で MMD 標準の日本語名に変換され、
  英語の元名は英語名の備考に書き込まれます。XPS も同様に規則で改名し、判別できない名前はそのまま残します。
－表情：ソースモデルに BlendShape / morph がない場合、PMX の表情も 0 となり、手作業で作成する必要があります。
－PSK / PSKX：PMX の IK / 付与(継承) / 剛体 / ジョイント / UV モーフ / マテリアルモーフは
  PSK に対応する構造がないため、すべてスキップされます。
  PMX の頂点は最大 4 本のボーンウェイトしか持てないため、元ファイルが 5〜6 本の場合は往復で欠落します。
  .psk という拡張子は PmxEditor のアンカーデータにも使われています（上記参照）。
－XPS / XNALara：バイナリ .xps のみ読み込めます。古いプレーンテキスト版は非対応で、明確にエラーを出します。
  この形式は BlendShape を保存しないため、出力される PMX の表情数は 0 です。
